# 插件调用提示

Apply the [request language rules](response-language.md). The examples below are Chinese. For English requests, use English plugin, service and tool names and write both disclosures in English.

本规则适用于「项目检查」插件的全部场景和 MCP，包括直接选择工具、不经过
场景 Skill 的调用。用户明确要求其他输出格式时尊重用户指令。

- 进入插件流程后，第一条可见回复的第一行必须使用 Markdown 加粗，说明
  插件、MCP 和本次要调用的工具。每次切换工具时，在调用前以相同格式提示；
  同时调用多个工具时合并成一行，列出各自的 MCP 和工具。
- 使用「项目检查」插件和「研发降本」「TRIZ 创新」「TRIZ 案例库」作为展示名称。
  工具名优先使用上游目录中的 `title`，缺少 `title` 时用当前语言描述工具功能。
- 尚未执行时写“准备调用”，不能提前写成已完成。首次需要读取流程说明时，
  如实提示「使用流程说明」工具，不提前声称已运行后续分析。
- 本轮最终回复的第一行也要加粗，汇总本轮实际调用的 MCP 和工具；成功、
  失败和未执行分别说明。仅启用 Skill、读取历史结果或打开旧页面，不等于
  本轮新调用了分析工具。不能把准备调用、连接失败或工具错误写成检查完成。
- 插件已启用但输入不足时，第一行说明“尚未调用工具”，再补问缺失信息；
  使用已有结果续聊时说明“复用已有结果，本轮未新调用工具”。未进入插件
  流程的普通问答不添加插件提示，也不为了显示提示而额外调用工具。
- 提示行使用标准 Markdown 加粗，不输出 HTML、ANSI 转义码或自定义颜色
  语法；回复文字的颜色由宿主控制。MCP Apps 页面的颜色由页面自身控制。

调用前示例：

**已启用「项目检查」插件｜准备调用「研发降本」MCP 的「系统成本分析」工具。**

调用成功后的首行示例：

**已调用「项目检查」插件 →「TRIZ 创新」MCP →「组件功能分析」工具，已返回结果。**

失败示例：

**「项目检查」插件 →「TRIZ 案例库」MCP →「TRIZ 案例检索」工具调用失败，本轮检索未完成。**
