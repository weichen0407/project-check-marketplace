# 项目检查工作区

项目档案和趋势看板使用当前插件中 `triz` 提供的工作区工具。

- 从当前项目的用户私有持久数据目录读取已保存的 Project Check 配置。同一个 Codex 项目沿用同一个工作区。已有配置时沿用 `workspace_token`。首次明确要保存产品或创建看板时，调用 `create_project_check_workspace`。
- 把返回的 `workspace_token` 保存在用户私有可写目录下的每项目配置中。优先使用宿主的用户私有数据目录。可用时使用 `~/.codex/project-check/workspaces/`，按项目根路径区分项目。不要把 token 存到 Git 工作树、公开文件或自动化提示词，也不要显示在回复中。宿主无法写入私有目录时，沿用当前会话内的工作区并说明再次打开时的限制。对演示查询可省略工作区。
- 保存每块看板的 `board_id` 以及对应的产品和市场，刷新时复用。用户只想查看时调用 `get_trends_board`。定时任务应读取同一项目的私有配置，任务提示词只记录配置路径和对应的看板。
- 云端工作区在最近一次保存后保留 180 天。工具找不到历史记录时，先查明工作区和看板是否选对。历史确实不可用时明确说明，并在下一次成功核查时重新建立基线。
