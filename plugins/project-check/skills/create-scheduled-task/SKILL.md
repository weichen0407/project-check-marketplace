# 创建定时任务

Follow the [request language rules](../project-check/references/response-language.md). For an English request, use English throughout this workflow.

宿主 Codex Automations 执行调度。插件提供调用指令和每轮检查方法。监测对象、
项目、频率、执行时间、时区和通知偏好在创建时按实际请求传入，由宿主保存
任务实例。插件清单、MCP 配置和分发包只记录可复用能力及服务入口。

## 何时创建

- 用户明确要求创建、启用或确认一个定时任务时，才执行创建这个外部状态变更。
  用户只说“能否增加此功能”、讨论模板或举例时，只说明能力或修改插件，不创建。
- 创建前明确任务对象、周期、执行时间和时区，按需取得输出位置和通知偏好。
  专利监测还需目标国家／地区。对象可以是产品、技术方案、公开号／申请号、
  申请人、竞争对手或技术关键词。能从当前对话可靠取得的内容直接复用。
- 用户提出多个对象时，默认用一项任务承载相同地域、频率和输出结构；只有范围、
  权限或周期明显不同才拆为多项任务，避免制造重复监测。

## 使用 Codex 调度能力

1. 查找 Codex 的 `automation_update`，按用户要求和实际工具 Schema 选择类型。
   用户明确要求 Cron Job 或独立项目作业时，使用 `kind=cron`。通过
   `list_projects` 确定目标项目，传入实际 `projectId`、宿主支持的本地执行
   环境、模型和推理设置，以及由本次请求得出的调度参数。目标项目不明确时先确认。
   依赖当前聊天上下文的普通周期跟进使用 `kind=heartbeat`。
2. 创建前检查同名或同范围自动化，优先更新现有任务。创建、更新、
   暂停、恢复、查看和删除都使用调度工具的相应模式。
3. 纯专利任务名称使用 `专利监测｜对象简名`（英文 `Patent Monitoring | Subject`）。
   按用户要求设定启用状态和通知。调度表达式及通知设置通过宿主工具字段传入，
   任务提示词记录工作范围和交付物。
4. 如果当前宿主没有 Codex 调度能力，明确说明未创建，并给出可复制的任务范围和
   提示词。

## 写入定时任务的提示词

调度器会重复执行提示词。独立 Cron Job 的提示词应包含每轮能访问的项目路径、
输入资料、核查范围和输出位置。需要比较上次结果时，使用该任务能访问的持久路径。

Record the selected language in the task prompt. For English requests, use an English task name and prompt, and instruct every scheduled run to return its status and deliverables in English.

涉及专利监测时，使用目标市场的专利局等官方公开来源，并保留以下范围和证据：

- 监测对象的精确标识或检索条件、目标国家／地区、法律状态／日期范围和排除项；
- 记录本轮实际查阅的专利公报或登记记录，保留可核实的来源链接。沿用用户确认的监测范围；
- 先读取当前任务中最近一次成功结果作为比较基线；首次运行明确标记“建立基线”。
  只有工具或来源实际返回变化字段时才声称法律状态、权利要求或专利族发生变化；
- 输出“新增／变化／无确认变化／失败或资料不足”四类状态。列出专利标识、发生
  日期、实际证据来源和与上次结果的差异；失败不能写成“没有变化”；
- 结果中保留限制和下一步；没有新证据时简短报告，不复述整份历史结果。

按监测对象选择任务内容：

- 已知公开号／申请号：按标识复查官方记录，并报告可验证变化。
- 申请人／竞争对手：按确认的地域与技术范围筛选新增公开记录，避免只凭名称相似
  就判定相关。
- 技术关键词／技术方案：复用已经确认的检索边界，筛选新出现的相关专利线索；
  检索结果是线索，不等于侵权或自由实施结论。

## 创建后的回复

只在调度工具返回成功后说明已创建或已更新，并列出用户可读的任务名称、频率、
监测范围和首次运行语义。不要显示内部 RRULE。提醒用户可以继续要求暂停、恢复、
改频率或删除；监测结果仍不是正式法律意见。
