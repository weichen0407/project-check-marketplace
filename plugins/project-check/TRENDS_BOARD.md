# 产品趋势看板

「项目检查」0.10.0 起可以为当前产品生成 **技术、专利、资讯**三栏看板。在 Codex 中点击任一条目，可打开厂商资料、专利公开文本或媒体原文。需要持续关注时，可以让 Codex Scheduled 按指定频率刷新同一看板。

## 快速开始

打开已有产品背景的 Codex 聊天，也可以先提供产品说明和目标市场，再使用通用指令。

> 使用 `$trends-board` 为当前产品生成技术、专利和资讯趋势看板。按我提供的技术重点和目标市场筛查，每个条目链接到原文。

看板显示来源、已知的日期和条目与项目的关系。技术栏优先厂商规格和其他原始技术资料。专利栏以专利局等官方公开资料为来源，显示文献号及可核实的公开或授权事件。资讯栏优先原始报道或品牌公告，仅有 RSS 时会标为摘录。日期未知时可留空，权利状态未经官方核实会标为待核。

## 在 Scheduled 中创建 Cron Job

独立 Cron Job 需要目标 Codex 项目、监测对象、周期、执行时间和时区。涉及专利时再提供目标市场。需要时可以指定看板的输出路径和通知偏好。

> 使用 `$create-scheduled-task` 创建一个独立 Cron Job，按我提供的项目、产品范围、频率、时间和时区刷新当前看板。

1. Codex 确定目标项目，并把看板保存在该项目下每次运行都能访问的位置。
2. 宿主返回创建成功后，可在 **Scheduled** 按任务名找到该任务。每次运行结果会提供更新后的看板。
3. 可用任务名更改执行时间、暂停或恢复。需要先看范围和安排时，可以要求只草拟调度。

产品和调度参数由 Codex 在创建任务时保存。插件配置声明通用能力和入口。定时运行依赖宿主调度能力、项目文件的持续访问和数据源可用性。普通聊天内周期跟进可以继续关联当前聊天。

## 怎样读刷新状态

英文看板使用 `"language": "en"`，标题、栏名和刷新状态会显示为英文。看板快照保存语言，后续刷新可继续沿用。

| 看板状态 | 对应的记录 |
| --- | --- |
| 已核对 | 本轮取得了足以更新该栏的证据，显示本轮核对的条目和来源。 |
| 无确认变化 | 本轮已核对范围内没有确认变化，保留上次有效条目。 |
| 来源核查未完成 | 显示实际错误或资料缺项。已有条目照常可打开，同时显示该栏上次成功日期。 |
| 暂无可核实条目 | 该栏当前没有可展示的证据条目。 |

看板页首日期是**本次检查日期**。条目日期以来源标注的发布时间、公告日或 RSS 日期为准。专利技术相关性和权利状态分别核对。看板用于跟踪线索和证据。

手动与定时刷新同时运行时，同一看板依次合并更新。较早核对日的结果会被拒绝。渲染器在看板目录保留一个隐藏的锁文件，供后续刷新共用。
